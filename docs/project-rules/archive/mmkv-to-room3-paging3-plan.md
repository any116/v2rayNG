# MMKV 到 Room 3、Paging 3 迁移计划

状态：待实施。

强制前置：factory-viewmodel-to-hilt-plan.md 的完整验收单通过。

## 1. 目标

1. 使用 Room 3 承载结构化持久化数据。
2. 使用 Paging 3 改善大型服务器列表读取。
3. 保留原 GUID、排序、订阅归属、当前选择和配置语义。
4. 保证迁移幂等、可恢复、可验证。
5. 覆盖服务、Widget、后台任务和外部入口。
6. 最终退出生产 MMKV 读写。

不先替换 UI 列表再补数据一致性。

## 2. 前置门禁

允许在 Hilt 完成前做只读盘点和方案评审。

以下操作必须等 Hilt 完成：
- 生产引入新存储选择逻辑。
- Repository 切换 Room。
- 开始正式导入用户数据。
- Paging 替换主列表。
- 移除 MMKV。

如 Hilt 未完成，停止后续生产迁移。

## 3. 当前存储清单

| MMKV 区域 | 内容 | 目标 |
|---|---|---|
| MAIN | 当前选择、订阅/分组索引、WebDAV 等 | 选择表、关联表、备份设置 |
| PROFILE_FULL_CONFIG | ProfileItem JSON | 配置元数据与 payload |
| SERVER_RAW | 原始自定义配置 | 独立 raw payload |
| SERVER_AFF | 测试延迟等附属状态 | 配置附属表 |
| SUB | 订阅信息 | Subscription |
| ASSET | 用户资源 URL | Asset |
| SETTING | 偏好、路由规则等 | 类型化设置与路由表 |

同时盘点：
- ANG_CONFIGS 历史索引。
- SUB_SERVERS_*。
- SUB_IDS。
- SELECTED_SERVER。
- DEFAULT_SUBSCRIPTION_ID。
- 当前分组缓存。
- 未知或历史 settings key。
- 导入导出备份中的旧字段。

清单以读写调用点为依据，不能只看常量定义。

建立匿名测试数据：

- 自定义 raw 配置。
- 跨组引用。
- 重复 GUID/损坏索引。
- 孤立正文。
- 当前选择不存在。
- 订阅列表缺失但分组索引存在。

## 5. R1：Room 3 技术基建

### 5.1 依赖

使用 Room 3 对应命名空间：
- androidx.room3。
- room3-runtime。
- room3-compiler。
- room3-paging。
- Room 3 Gradle 插件。
- 测试支持。
- 选定的 SQLiteDriver。

Paging 3 使用 paging-runtime、paging-compose 和必要测试库。

版本统一登记版本目录。
Room 3 runtime、compiler、plugin、paging 集成版本保持兼容。

### 5.2 API 边界

Room 3 不是把 Room 2 的版本数字改为 3：
- KSP 代码生成。
- Kotlin DAO。
- 协程驱动访问。
- 驱动与连接 API。
- Schema/migration API 按选定版本实现。
- 不直接复制 SupportSQLiteDatabase 事务样板。

### 5.3 Paging 返回类型

根据 Room 3 官方接口，在 Database 或 DAO 注册：

PagingSourceDaoReturnTypeConverter

使用 @DaoReturnTypeConverters 完成注册。

仅添加 room3-paging 依赖不能替代返回类型转换器声明。

### 5.4 工程配置

新增目标目录：
- 数据库定义。
- DAO。
- Entity。
- Mapper。
- Migration。
- MMKV 导入器。
- 存储切换协调器。

Schema 导出到明确目录并提交版本管理。

数据库版本号是业务 schema 版本，不与 Room 库版本号绑定。

## 6. R2：目标数据模型

### 6.1 配置

建议分离：
- Profile：GUID、名称、类型、可搜索字段、更新时间。
- ProfilePayload：完整兼容 JSON。
- ProfileRaw：自定义原文。
- ProfileAffiliation：测试结果及更新时间。

列表查询只读轻量投影，不载入全部 payload。

保留 payload 是为了兼容复杂配置，不表示放弃结构化查询。
用于筛选和排序的字段必须有明确列或索引。

### 6.2 订阅与顺序

- Subscription：ID、属性、订阅顺序。
- SubscriptionProfile：subscriptionId、profileGuid、position。
- Selection：当前选中 GUID、当前显示分组。

初始设计采用关联表，保留现有潜在跨组引用。
不得在未验证之前强行改成“一份配置只能属于一个组”。

默认订阅持久化为明确记录。
“全部”页只作为查询视图，不创建伪订阅。

排序使用明确 order/position，加 GUID 等稳定次级排序键。

### 6.3 路由

保留规则顺序和原匹配语义。

规则集、规则内容和顺序分开建模。
无法安全拆解的复杂字段先保留兼容 JSON，随后按实际查询需求规范化。

### 6.4 设置

将 settings key 分类：
- 强类型业务设置。
- 启动关键设置。
- UI 偏好。
- 历史未知项。
- 敏感凭证。

未知旧 key 先保存到带类型标签的兼容设置表，避免无声丢失。

最终退出 MMKV 包括 SETTING。
如果决定保留其他键值存储，必须作为范围变更评审，不能在“MMKV 已全部迁移”结论中隐藏。

### 6.5 文件资源

Room 保存资源元数据，不把大型文件和 Bitmap 直接放入普通业务表。

## 7. R3：跨进程策略

### 7.1 当前事实

UI、服务、Widget 和 WorkManager 涉及不同进程。

Hilt Singleton 只在各自进程内生效。
单进程 Mutex 不能保护全局迁移。

### 7.2 方案验证

迁移试点必须验证所选 Room 3 版本、驱动和多实例失效机制是否覆盖需求。

推荐优先验证：
- 同一数据库文件。
- 每进程一个数据库实例。
- 显式事务。
- 经验证的跨进程失效通知。
- 统一存储代际与初始化门禁。

通知只说明“数据变了”，不承担事务和写入互斥。

若选定组合不能可靠传播跨进程失效：
- 增加明确 IPC 变更通知并重新查询。
- 或评审单一数据所有者服务/Provider。

该项不通过，不得切换生产。

### 7.3 实时服务状态

数据库不作为服务是否正在运行的唯一依据。

运行状态通过现有服务协议重新确认。
数据库记录配置和必要历史，不把持久化的 running=true 当成实时事实。

### 7.4 同步读取接缝

当前 ThemeManager、SettingsManager 和服务路径有同步 MMKV 读取。

迁移目标：
- 异步加载。
- 明确初始化状态。
- 在依赖设置的动作前 awaitReady。
- 内存快照由 Repository 管理并失效更新。

不在 getter 中使用 runBlocking 查询 Room。

对于系统同步回调，预先准备可验证快照，或将动作转交受控异步流程。
不能为了启动速度继续长期双写 MMKV。

## 8. R4：一致快照与写入冻结

### 8.1 统一写入口

迁移前先让所有生产写入经过可控制的数据门面，包括：
- UI。
- 订阅更新。
- 服务测试结果。
- Widget。
- 快捷入口。
- 备份恢复。
- 后台任务。

未受控的旧写入口存在时，不开始导入。

### 8.2 全局锁

使用能跨进程生效的协调机制，例如应用私有文件锁配合迁移状态。

所有参与者遵守同一锁顺序。
不能只锁 MAIN 就假定其他 MMKV 区域写入已经停止。

迁移期间：
- 禁止新配置修改。
- 等待已开始的写操作结束。
- 暂停可能写附属状态的任务。
- 不允许后台恢复同时执行。
- UI 展示迁移中。

活动连接如何处理必须明确：
- 保持旧快照继续运行但禁止写入，或
- 在用户确认下停止。
不能隐式中断正在运行的连接。

### 8.3 备份

在稳定快照上使用 MMKV 支持的备份方式或经验证的文件快照。

不能直接复制正在并发写入的 mmap 文件后宣称得到一致备份。

备份写入应用私有目录，记录：
- 存储区域。
- 长度和校验值。
- 迁移格式版本。
- 数据代际。

备份不输出敏感正文到日志。

## 9. R5：导入算法

### 9.1 状态机

NotStarted
→ SnapshotReady
→ Importing
→ Validating
→ Ready

失败进入 RecoverableFailure，保留快照与错误阶段。

### 9.2 导入顺序

1. 读取并验证订阅及默认订阅。
2. 读取全部配置正文，不只依赖 SUB_IDS。
3. 导入 raw 和附属状态。
4. 恢复 SUB_SERVERS_* 关联与顺序。
5. 处理历史 ANG_CONFIGS。
6. 恢复当前选择。
7. 导入资源、路由、设置和 WebDAV。
8. 运行一致性检查。
9. 原子发布 Ready 标记。

### 9.3 大数据

使用稳定源快照分批写入目标表。
导入期间新库不可被正常业务读取。

数据量较小时可单事务。
大数据量采用导入代际和最终提交标记，保证半成品不可见。

不把所有配置一次性读入巨大 List。

### 9.4 幂等

使用原 GUID、唯一约束和迁移代际防止重复导入。

数据库中的完成标记与最终一致性状态在同一事务提交。

进程在提交后、外部标记更新前死亡时，以数据库完成记录为准，不能重新覆盖用户已开始写入的新数据。

### 9.5 损坏数据

区分：
- 缺失索引。
- 缺失正文。
- 非法 JSON。
- 悬空当前选择。
- 孤立 payload。
- 重复关联。

原则：
- 能保留的原文保留到隔离表或私有恢复文件。
- 不确定是否孤立时不删除。
- 当前选择优先按原 GUID 恢复。
- 不可恢复项进入报告并提供导出恢复路径。
- 部分数据损坏不自动触发全部清库。

## 10. R6：切换与回滚

### 10.1 单一事实源

切换成功后，同一数据域只写 Room。

不长期双写 MMKV 和 Room。
需要观察期时可以做只读对比，但不能形成两个可写真相。

所有进程通过统一 readiness 与代际判断选择新库。

### 10.2 失败回退

首次 Ready 前：
- 新库不对业务发布。
- 失败恢复旧 MMKV。
- 保留失败报告并允许重试。

Ready 后：
- 用户可能已经产生新数据。
- 不能直接切回旧 MMKV 快照。
- 回退必须将新数据反向导出并验证，或者明确不支持旧版本直接读取。

“保留旧文件”不是完整回滚方案。

### 10.3 旧数据清理

至少在：
- 多次启动验证。
- 备份恢复通过。
- 跨进程行为通过。
- 回滚策略确认。
之后再清理旧数据。

删除操作单独记录，不与首次导入同一提交执行。

## 11. R7：Repository 切换

按数据域替换 MMKV 调用。

提供：
- observeSubscriptions。
- observeSelection。
- 查询轻量服务器投影。
- 按 GUID 获取完整配置。
- 保存与删除。
- 订阅替换事务。
- 排序事务。
- 批量测试结果写入。
- 设置观察。

命名可与既有接口协调，不要求机械更名。

MainRepository 的服务广播连接与数据库访问可分离，但每次重构保持可测试的生命周期边界。

## 12. R8：Paging 3 接入

### 12.1 数据链

DAO PagingSource
→ Repository Pager
→ ViewModel 按筛选条件构建 Flow
→ cachedIn(viewModelScope)
→ Compose collectAsLazyPagingItems

PagingData 单独暴露。
不强制塞进 BaseUiState，也不改写 BaseScreen 的事件契约。

### 12.2 查询

查询条件至少包括：
- 当前分组。
- 搜索条件。
- 排序模式。
- 必要的显示过滤。

使用参数化 SQL。
排序模式映射固定 SQL，不拼接不可信列名。

切组和搜索使用 flatMapLatest 取消旧 Pager。
每个查询采用稳定排序和次级 GUID。

### 12.3 搜索语义

当前 MainViewModel 使用 Regex、matchesPattern，并匹配 remarks、statistics、typeDescription。

不能直接改为 LIKE 后声称行为等价。

实施前建立当前搜索真值测试。

可选实现：
- 兼容模式先计算匹配 GUID，再按数据库结果分页。
- 使用可验证的匹配索引/临时结果表。
- 经需求评审后明确改变为普通文本搜索。

复杂正则需限制耗时和输入规模，避免阻塞页面。
不能只筛选已经加载的当前页。

### 12.4 LoadState

区分：
- 首次加载。
- 首次错误。
- 空结果。
- append 加载。
- append 失败。
- 刷新失败但保留旧内容。

“空”只在加载完成且确实无 item 时显示。

### 12.5 批量操作

删除全部、导出全部、去重和测试全部必须基于完整查询范围。

不能以 itemSnapshotList 作为“全部数据”。

全选可以建模为：
- 查询快照 + 排除集合，或
- 明确的 GUID 集合。

操作开始后明确固定范围还是动态范围，避免搜索变化改变删除目标。

### 12.6 排序与拖动

Paging 下索引只代表当前呈现位置。

提交拖动使用：
- movedGuid。
- beforeGuid/afterGuid。
- 分组 ID。
- 必要的版本条件。

在事务中重排。
不把当前加载页写成该组完整顺序。

必须测试跨页边界移动、并发订阅更新和排序冲突。
无法安全实现跨页拖动时提供明确替代操作，不静默丢失原功能。

### 12.7 定位选中节点

不能为了定位一个 GUID 加载全部分页。

通过同一查询和排序计算位置或锚点。
处理：
- 节点不在当前过滤范围。
- 节点已删除。
- 当前页尚未加载。
- 分组切换。

保持 MainEvent.LocateProfile 既有用户语义。

### 12.8 高频测速

测试结果持久化和列表失效需要合并。

避免每个测试回调都触发全列表 PagingSource 失效。
选择短批量写入或单独的轻量结果流。

最终结果必须落库并通知。
排序按延迟变化时明确是否实时跳动，防止列表不断重排。

## 13. 订阅更新事务

流程：
1. 网络读取。
2. 完整解析。
3. 验证结果。
4. 计算替换映射和当前选择。
5. 数据库事务提交。
6. 发布变更。
7. 清理无引用 payload。

网络请求不放在数据库长事务内。

失败不清空原订阅。
被其他组引用或仍被当前选择保护的数据不得直接删除。

## 14. 备份与恢复

保持外部备份格式兼容，不直接暴露数据库表结构作为唯一备份格式。

恢复先解析为中间模型，再通过 Repository 事务写入。

提供：
- 旧 MMKV 时代备份导入。
- 新格式版本标记。
- 覆盖范围确认。
- 凭证处理。
- 部分失败报告。
- 主题、服务和 Widget 刷新。

不能直接复制打开中的数据库文件而忽略 WAL。

## 15. 测试矩阵

### 正确性
- GUID 不变。
- 默认订阅不丢。
- 分组顺序不变。
- 组内顺序不变。
- 当前选择正确。
- raw 原文保留。
- 路由顺序保留。
- 设置类型和默认值不变。

### 故障注入
- 每一迁移阶段强杀进程。
- 磁盘不足。
- 数据库写失败。
- MMKV 损坏。
- 目标库已存在但未完成。
- Ready 提交后立即死亡。
- 重复执行迁移。
- 导入期间后台任务启动。
- 应用降级与旧格式恢复。

### 跨进程
- UI 写、服务读。
- 服务写测试结果、UI 更新。
- Widget 首次启动。
- 后台订阅更新。
- 一个进程长期未退出。
- 数据代际变化后重新读取。

### Paging
- 快速搜索和切组。
- 分页边界。
- 删除当前页最后一个元素。
- 筛选后全选。
- 全量导出。
- 正则兼容。
- 跨页排序。
- 定位当前节点。
- 高频测试更新。
- 大列表内存和首屏性能。

### Schema
每次升级测试旧 schema 到新 schema。
用户数据不使用 destructive migration。

## 16. 性能验收

对比 R0 基线。

必须报告实际数值：
- 首屏时间。
- 峰值内存。
- 搜索耗时。
- 导入耗时。
- 数据库大小。
- 主线程阻塞。
- 跨进程更新延迟。

不预设“Room 一定更快”或“Paging 必然减少所有内存”。
