# Logcat 读取、缓存与清理

## 原因

原实现仅截取最近 2000 行，低日志量时历史错误可一直留在 logd 中。
页面只有手动刷新，内存快照也不会过期。
清理水位使用 `MM-dd HH:mm:ss.SSS`，`SimpleDateFormat` 缺少年份时按 1970 年解析，
随后又被一年有效期校验拒绝；系统 `logcat -c` 无权限时，清理并不能阻止历史记录回流。

## 数据链路

- 读取使用 `logcat -d -t 2000 -v time -v epoch`，保留原有四组 tag 与应用 UID 下的多进程日志。
  epoch 毫秒用于比较，页面转成本地时间；复制和导出保留原始文本。
- 每次读取最多等待 5 秒，取消或超时销毁子进程并关闭管道。
  非零退出码作为读取失败处理，不把 stderr 或 buffer 分隔行当成日志。
- 快照同时受 6 小时、2000 行、1 MiB UTF-8 文本限制，单行超过 16 Ki 字符丢弃。
  保持最新在前，重复错误不去重，不按等级提前删除仍在窗口内的诊断信息。
- 页面 STARTED 时立即读取，此后每 10 秒先淘汰过期快照，再尝试刷新。
  即使读取挂起或失败，也能淘汰缓存；STOPPED 时取消读取并释放快照。
  搜索不改变原始快照，复制与分享再次校验有效期及清理水位。
- 日志列表不进入 `LogcatUiState`，数据链为 Repository 的内存 `PagingSource` / `Pager` →
  ViewModel 的 `Flow<PagingData<LogLine>>` / `cachedIn(viewModelScope)` → Compose 的
  `collectAsLazyPagingItems()`；UiState 只保存搜索条件与搜索模式。
  每页 40 行、首次 80 行、预取 20 行，启用占位与跳转（阈值 240）。页面按需解析显示文本，
  未加载项显示不可操作的占位行；滚动不会重新启动 logcat 子进程。
- 日志记录在筛选前分配进程内单调 ID，读取新快照时按完整原文从旧到新匹配已有记录。
  新增记录与新增的相同原文重复项获得新 ID，已有记录在搜索和刷新时复用 ID；
  不使用行位置或原文 hash 作为 key，不去重。logcat 不提供记录序列号，完全相同的重复项
  无法单独辨认，按旧项优先复用身份。匹配表仅存在于本次快照计算，不积累历史日志。
  同一个 Pager 在快照改变时失效刷新，通过记录 ID 找回滚动锚点；筛选移除锚点时回退到有效位置。
  复制全部与分享使用完整的筛选快照，包含尚未加载的页，不能从 `itemSnapshotList` 截取导出。
- 清理优先取消旧读取，再通过共享 Repository 的 Mutex 串行写入 Room 中的 epoch 毫秒水位。
  已开始的水位写入不可取消，写入成功才清空页面；同一毫秒及更早记录均被排除。
  不再尝试清空系统缓冲区，也不需要 logd 清理权限。
  兼容旧 epoch 数值及无年份时间串，后者按当前年/上一年严格解析。
- 分享生成独立随机文件名，不会因下一次分享删除前一个文件。
  在读取/分享时清理超过 24 小时或数量超过 3 个的导出；主动清理也删除这些文件。
  清理只触及 `cache/shared_logs/v2rayNG_logcat_*.txt`，不影响其他缓存。
  页面关闭后不启动后台清理任务，未再次使用时由 Android 缓存回收负责磁盘回收。

## 参数与资源预算

- 6 小时是日志显示的最大时间窗口，为长时间复现问题和整理日志留出时间；仍受最近 2000 行、
  1 MiB 文本及系统 logd 缓冲区覆盖限制，不保证能取回完整的 6 小时日志。
  放宽时间窗口不会提高行数或文本字节上限。1 MiB 指原始 UTF-8 文本，实际堆内存还包括
  字符串、列表、解析后的行模型及读取/过滤期间的临时对象。
- 10 秒轮询只在页面 STARTED 时运行，周期读取约每分钟 6 次，每次都会启动 logcat 子进程
  并重读最近最多 2000 行。相较 5 秒轮询，周期性进程启动和重复读取的频率减半；
  IO、解析和过滤在后台 dispatcher 执行，已有读取未完成时跳过本次读取，空闲时手动刷新可立即触发。
  这是静态资源预算，实际 CPU、耗电和帧率需要真机测量。
- 保留最近 3 份分享文件，兼顾连续分享和磁盘占用。正常清理后，新生成导出的总量约不超过
  3 MiB 加换行符；新文件写入并修剪期间会短暂多出一份。24 小时到期清理在下一次读取或分享时执行。

## 回归覆盖

`LogcatBufferTest`：清理边界、旧水位跨年、非法水位、无新增日志时过期、行数/字节上限。
`LogcatReaderTest`：命令参数、非零退出、读取阻塞超时、取消及超长行。
`LogcatExportsTest`：连续分享、有效期、数量上限、清理隔离。
`LogcatViewModelTest`：页面生命周期、读取挂起时过期、清理抢占、搜索及过期日志禁止导出。
同时覆盖刷新/搜索后的重复项 ID，以及未加载页参与复制和分享。
`LogcatRecordIdsTest`：新增日志、相同原文重复项、淘汰旧项与清理后的 ID 分配。
`LogcatPagingSourceTest`：分页边界、加载后续页、空快照、新增日志后的锚点定位及未加载区跳转。
`LogcatContractTest`：epoch 显示时间转换、原始文本及记录 ID 保留。

## 真机检查步骤

1. 产生一条应用错误后打开日志页，确认时间可读、内容完整；无新增日志等待 6 小时，
   应在下一个 10 秒周期内消失，而不是依赖系统日志覆盖。
2. 刷新进行中点击清理，随后刷新、关闭重开日志页、重启应用，旧记录不应再出现；
   清理后产生的新日志应正常显示，包含 `:daemon` / `:tasks` 进程。
3. 搜索错误内容，等待自动刷新，搜索条件应保持；退出搜索立即恢复未过滤的有效日志。
4. 日志页进入后台，确认不再运行读取子进程；返回后立即重新读取。
5. 连续两次分享，两个接收方均能读取各自文件；主动清理后应用内导出缓存消失。
6. 产生超过 80 行日志，滚动到中间后等待刷新，确认原记录仍可定位；连续相同错误不应合并。
   搜索再退出搜索，记录 key 应复用；不滚动加载后续页就复制/分享，内容仍应包含全部有效匹配项。
